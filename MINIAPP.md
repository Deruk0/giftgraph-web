# GiftGraph Mini App

**Текущая схема: сайт и архив полностью на Vercel + Blob, бот на ПК. Туннель не нужен.**
Актуальные команды и настройки: [CLOUD.md](CLOUD.md).

## Прежние варианты с туннелем и DuckDNS

Текущая выбранная схема: Vercel как публичный вход сайта и Mini App, бот и все данные на ПК. Подготовка и публикация описаны в `vercel/README.md`. Инструкции прямого размещения на DuckDNS ниже остаются альтернативой; в схеме Vercel DuckDNS может использоваться как адрес локального backend после настройки HTTPS.

Сайт адаптирован для открытия внутри Telegram. Кнопка в `/start`, команда `/app`, кнопка меню GiftGraph и кнопка под результатом `/search` открывают Mini App в личном чате. В группах результаты открываются обычной ссылкой. Построение новых графов пока выполняется командой `/search` в боте; Mini App показывает архив и интерактивные графы.

Публичный сайт опубликован: https://giftgraph-miniapp.vercel.app. Для текущей схемы запуска используйте `publish.ps1` и `tg_gift_bot/manage.ps1`; инструкции прямого доступа через DuckDNS ниже относятся к альтернативному варианту.

## Настройки

В `tg_gift_bot/.env` уже установлено:

```env
GIFTGRAPH_WEB_URL=https://giftgraph-miniapp.vercel.app
GIFTGRAPH_WEB_API_URL=http://127.0.0.1:5100
```

Секрет API сохранен. `manage.ps1` читает его из настроек бота.

## Запуск на ПК

```powershell
cd "C:\Users\admin\Documents\Vibe Code Projects\tg"
.\giftgraph-web\manage.ps1 restart
cd .\tg_gift_bot
.\.venv\Scripts\python.exe main.py
```

Для нового компьютера создайте окружение сервера и установите зависимости:

```powershell
python -m venv giftgraph-web/.venv
.\giftgraph-web\.venv\Scripts\python.exe -m pip install -r giftgraph-web/requirements.txt
```

## Публичный HTTPS

DNS сам по себе не открывает доступ к ПК. Для Mini App адрес `https://giftgraph.duckdns.org/health` должен быть доступен извне с доверенным сертификатом и возвращать JSON со `status: ok`.

Для прямого доступа нужны публичный IP, проброс портов на роутере и HTTPS reverse proxy, направляющий запросы на `127.0.0.1:5100`. Не открывайте порт Flask 5100 напрямую в интернет. При CG-NAT нужен туннель или промежуточный сервер. Настройки VPN и роутера не изменялись: сначала следует проверить, какой IP указан в DuckDNS и на какой сервер он ведет.

Пользователь подтвердил, что в DuckDNS указан домашний внешний IP. Подготовлен `Caddyfile` для HTTPS reverse proxy. Caddy пока не установлен. После установки Caddy и настройки доступа извне запуск из папки `giftgraph-web`:

```powershell
caddy run --config .\Caddyfile --adapter caddyfile
```

На роутере нужно перенаправить внешний TCP 80 на TCP 80 этого ПК и внешний TCP 443 на TCP 443 этого ПК, а в брандмауэре Windows разрешить эти входящие подключения. Локальный IP ПК следует закрепить в DHCP роутера. Caddy получает и обновляет сертификат автоматически после того, как домен и входящие подключения заработают.

Проверка 2026-10-07: DNS домена разрешается, но публичный HTTPS недоступен из среды настройки. Локальные тесты не подтверждают работу домена в Telegram.

После подключения HTTPS перезапустите бота: он сам установит кнопку меню. Затем отправьте ему `/app` в личном чате. Для кнопки в профиле дополнительно откройте @BotFather → `/mybots` → свой бот → Bot Settings → Configure Mini App и укажите `https://giftgraph.duckdns.org` как адрес основного приложения.

## Проверка

1. Открыть `/app` в личном чате бота — архив должен открыться внутри Telegram.
2. Открыть граф и нажать кнопку возврата Telegram — вернуться в архив.
3. Выполнить `/search @username` — открыть результат кнопкой внутри Telegram.
4. Проверить обычный браузер — архив и графы продолжают открываться.

Telegram launch data используется только для интерфейса. Авторизация пользователя и новые защищенные операции через Mini App не добавлялись.
