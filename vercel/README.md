# Vercel + закрытый Blob

Текущая облачная схема и команды: [../CLOUD.md](../CLOUD.md).
Сайт работает независимо от ПК; посредник и туннель больше не используются.

## Прежняя схема с посредником (для возврата)

Vercel дает публичную HTTPS-точку входа для сайта и Mini App. Существующие страницы формируются локальным Flask-сервером и передаются через шлюз Vercel. Бот, Telethon, SQLite и HTML-графы остаются на ПК. Supabase не используется.

Если ПК, локальный сервер или туннель выключены, архив недоступен. Vercel показывает страницу с кнопкой повторной загрузки. Vercel не хранит копии графов.

## На ПК

Запустить `giftgraph-web/manage.ps1 start`, затем бота из `tg_gift_bot`. Локальный API остается `http://127.0.0.1:5100`.

Нужен публичный HTTPS-адрес локального сервера: стабильный туннель либо прямой доступ через `giftgraph.duckdns.org` с HTTPS-прокси. `localhost` и домашний LAN-IP недоступны Vercel. Адрес должен открывать `/health` извне и возвращать JSON `status: ok`.

Туннель следует направлять только на порт сайта 5100. Смена исходящего IP из-за личного VPN сама по себе не дает входящего доступа к ПК.

## В Vercel

1. Загружать только эту папку `giftgraph-web/vercel`. Если импортируется Git-репозиторий, установить Root Directory на эту папку относительно корня импортированного репозитория. Не импортировать секреты и Telegram-сессию бота.
2. Framework Preset: Flask.
3. Добавить переменную окружения `GIFTGRAPH_BACKEND_URL` с публичным HTTPS-адресом сервера на ПК, без пути. Например, `https://giftgraph.duckdns.org`, но только после настройки его HTTPS. Не указывать здесь адрес проекта Vercel.
4. Deploy. Записать реальный адрес проекта `https://<имя-проекта>.vercel.app`.

## Настройки бота

После публикации установить в `tg_gift_bot/.env`:

```env
GIFTGRAPH_WEB_URL=https://giftgraph-miniapp.vercel.app
GIFTGRAPH_WEB_API_URL=http://127.0.0.1:5100
```

Существующий `GIFTGRAPH_WEB_SECRET` сохранить. В Vercel его добавлять не нужно: шлюз не загружает новые графы от имени бота. Перезапустить бота, открыть `/app` в личном чате. Для основной Mini App в профиле бота поставить тот же адрес Vercel в @BotFather.

Если меняется адрес туннеля, обновить `GIFTGRAPH_BACKEND_URL` в Vercel и сделать Redeploy. Публичный адрес Mini App и настройки бота при этом остаются прежними.

## Проверка

- `/health` на Vercel возвращает JSON локального сервера.
- `/app` открывает архив и графы в Telegram; кнопка возврата работает.
- `/search` сохраняет граф на ПК и возвращает ссылку на Vercel.
- Удаление графа передает его собственный токен; запрос без токена не получает прав администратора.
- При остановке ПК Vercel возвращает 503 и страницу временной недоступности.

Опубликовано 2026-10-07: https://giftgraph-miniapp.vercel.app. Проект `giftgraph-miniapp` связан с аккаунтом Vercel; публичные `/health`, архив, граф и SDK проверены без входа в Vercel. В боте `@tg_chain_gift_person_bot` установлена и проверена кнопка меню. Бот запущен на ПК и вошел в polling.

## Перезапуск после выключения ПК

```powershell
cd "C:\Users\admin\Documents\Vibe Code Projects\tg"
.\giftgraph-web\publish.ps1
.\tg_gift_bot\manage.ps1 start
```

`publish.ps1` запускает локальный сервер и SSH-туннель localhost.run, проверяет публичный `/health` и обновляет Vercel с актуальным адресом backend. Публичный адрес Mini App сохраняется. Не нужно запускать вторую копию бота вручную.

Проверить состояние:

```powershell
.\giftgraph-web\manage.ps1 status
.\giftgraph-web\tunnel.ps1 status
.\tg_gift_bot\manage.ps1 status
```

Остановка:

```powershell
.\tg_gift_bot\manage.ps1 stop
.\giftgraph-web\tunnel.ps1 stop
.\giftgraph-web\manage.ps1 stop
```

SSH-туннель localhost.run бесплатный и временный: имя может измениться даже при работающем соединении. Если сайт показывает недоступность при включенном ПК, запустите `publish.ps1` повторно. Для постоянной работы нужен стабильный туннель или прямой HTTPS-доступ к домашнему IP. [Описание ограничений](https://localhost.run/docs/forever-free/).

Cloudflare Quick Tunnel не подключился из текущей сети (TLS EOF); неиспользуемый процесс остановлен. Активен только туннель SSH. Личный VPN и роутер не перенастраивались.
